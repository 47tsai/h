# 本機資料與 GitHub 同步設計

> 狀態：前端同步流程、Worker 與刪除標記已實作；Worker 密碼驗證應保持啟用。注意：目前部署文件指出同步檔案位於公開儲存庫，因此不可用於敏感資料；要同步私人資料，必須先遷移至私人儲存庫並確認 Worker 設定。此文件以「平常只用本機資料，需要時在設定頁手動同步」為基礎。

## 1. 設計目標

- 本機是日常使用的主要資料來源；沒有網路或同步服務故障時，核心功能仍可使用。
- 使用者只有在設定頁主動發起同步時，才需要輸入獨立的同步密碼。
- Cloudflare Worker 負責驗證同步密碼，並代替瀏覽器呼叫 GitHub API。
- GitHub 儲存庫保存同步資料；前端不直接持有 GitHub Token。部署前必須確認儲存庫可見性，公開儲存庫的同步內容任何人都可能讀取。
- 同步成功與否必須清楚回報，不得把尚未上傳的資料顯示成已同步。

## 2. 元件與責任

### 網站前端
- 日常讀寫 IndexedDB。
- 設定頁提供「上傳／下載／雙向同步」等清楚操作；第一版可先做「雙向同步」。
- 同步時將必要資料送往固定的 Worker HTTPS endpoint。
- 不在 localStorage、IndexedDB、網址、分析事件或一般日誌中保存同步密碼。
- 不把 GitHub Token、Worker 的伺服器端密鑰或其他長期憑證打包進前端。

### Cloudflare Worker
- 只接受預先定義的同步操作，不提供任意 GitHub API 代理。
- 驗證同步密碼，限制錯誤嘗試與請求頻率，檢查請求大小及資料結構。
- 只操作設定好的單一 GitHub 儲存庫與固定資料路徑，不接受客戶端任意指定目標。
- 使用 Worker Secrets 保存 GitHub Token 與同步密碼（或其驗證材料）；不得放在程式碼、公開環境變數檔或 Git 儲存庫。
- 對外只回傳必要的同步結果，不回傳 Token 或其他秘密。
- 不記錄密碼、Authorization 標頭或完整私人同步資料。

### GitHub
- 使用私有儲存庫保存使用者的同步資料。
- Token 儘可能限制到目標儲存庫及必要的 Contents 讀寫權限。
- 同步資料採明確版本格式，包含 schema version、資料更新時間與資料項目。

## 3. 密碼與端點安全

這個密碼應是**專案專用的同步密碼**，不是 GitHub 帳號密碼，也不是 GitHub Personal Access Token。

- 使用高熵、不可猜測的長密碼；不要使用生日、常用密碼或可從公開資料推測的內容。
- 網站與 Worker 全程使用 HTTPS。
- 每次手動同步時輸入密碼；第一版不保存密碼，也不放進 URL 或查詢參數。
- Worker 以伺服器端 Secret 驗證密碼，並實施速率限制、失敗延遲或暫時封鎖等防暴力猜測措施。
- 可額外使用 Cloudflare Turnstile 或其他反濫用措施，但不能把它當成唯一驗證機制。
- 對錯誤驗證回傳一般化訊息，不暴露伺服器 Secret 或 GitHub 權限細節。
- 密碼成功驗證後，只執行允許的同步操作。不得讓密碼變成可呼叫任意 URL、讀取任意檔案或操作其他儲存庫的通用代理憑證。
- 若未來想避免每次傳送密碼，可改為換取短效、受限的同步工作階段憑證；短效憑證需設期限且不應長期持久化。

## 4. 建議同步流程

1. 使用者在設定頁選擇「立即同步」。
2. 前端檢查本機資料，顯示本機待同步項目數量。
3. 使用者輸入專用同步密碼。
4. 前端透過 HTTPS 將密碼及同步請求送到固定 Worker endpoint。
5. Worker 驗證密碼、請求大小、資料結構與頻率限制。
6. Worker 從固定 GitHub 路徑讀取雲端資料與版本資訊。
7. Worker／前端依既定合併規則整合本機與雲端資料，檢查衝突。
8. 合併結果寫回 GitHub；處理 GitHub SHA／版本變更，避免覆寫其他裝置剛上傳的資料。
9. 成功後更新本機最後同步時間與遠端版本；失敗時保留本機資料並顯示可理解的錯誤。
10. 完成後清除前端記憶體中的密碼，不保留在持久化儲存中。

## 5. 同步資料與衝突處理

- 每筆歷史、收藏與碼表紀錄使用穩定且唯一的 ID。
- 資料項目帶有 schema version、createdAt、updatedAt；刪除操作使用刪除標記（tombstone），避免刪除的項目在下次同步時復活。
- 不以「整份本機 JSON 無條件覆蓋雲端」作為預設方式，避免另一台裝置的資料遺失。
- 第一版可依項目 ID 合併不同資料；同一 ID 出現不同版本時，需定義可預期的衝突規則，必要時保留兩份或提示使用者選擇。
- GitHub 更新應使用讀取到的檔案 SHA／版本做條件更新；若雲端已被其他裝置修改，重新讀取並合併，而不是直接覆寫。
- 同步資料應有合理大小上限；歷史記錄可設定保留政策，避免單一 JSON 無限制膨脹。
- 若未來資料量增加，可將同步檔案按資料類型或分區拆分，並在需要前先評估 GitHub Contents API 的限制。

## 6. 第一版建議範圍

- 本機資料：IndexedDB。
- 遠端資料：一個固定的 JSON 資料檔，先保存歷史、收藏、碼表紀錄與必要設定。
- 操作：手動雙向同步。
- 驗證：專用同步密碼；不儲存密碼。
- 服務端：Cloudflare Worker + Worker Secrets。
- GitHub：私人儲存庫及最小必要權限的 Token。現行公開儲存庫設定不符合私人資料同步要求，遷移完成前不得同步敏感內容。
- 狀態：最後成功同步時間、待同步變更數、同步中、成功、失敗與衝突提示。
- 暫不做自動背景同步、多帳號、多儲存庫或複雜的版本歷史 UI。

## 7. 實作前驗收清單

- [ ] 前端產物中找不到 GitHub Token 或 Worker 私密密鑰。
- [ ] 密碼不會出現在 URL、持久化儲存或日誌。
- [ ] 未帶正確密碼的請求無法讀寫 GitHub。
- [ ] Worker 只允許操作固定儲存庫與固定路徑。
- [ ] 錯誤密碼與大量請求會受到速率限制。
- [ ] 離線、Worker 錯誤、GitHub API 失敗時，本機資料仍完整。
- [ ] 兩台裝置先後同步不會因整檔覆蓋而遺失資料。
- [ ] 刪除紀錄不會在下一次同步時重新出現。
- [ ] 同步狀態只在確認 GitHub 寫入成功後更新。
- [ ] 使用者可理解同步範圍、雲端儲存位置與如何清除資料。
