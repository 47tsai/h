# 頁面配置與網站來源規劃

> 狀態：規劃中。本文件先定義頁面職責、互動流程與來源擴充規格；具體來源名單及網址規則待確認後再加入。

## 1. 導覽架構

### 桌面版
- 頂部區域：專案標誌／名稱、全域搜尋（若適用）、主題切換、GitHub 同步狀態。
- 主要導覽：轉換器、歷史記錄、收藏、碼表、碼表紀錄、設定。
- 內容區：依目前頁面呈現主要工作內容，避免把所有功能塞在首頁。

### 手機版
- 主要操作優先放在首屏，輸入框與主要按鈕要方便單手觸控。
- 使用精簡導覽（可評估底部導覽或可收合選單）；不要讓導覽遮住計時器或主要內容。
- 長清單採清楚的搜尋、篩選與分頁／漸進載入方式。
- 尊重安全區域、窄螢幕與虛擬鍵盤，避免操作按鈕被遮擋。

## 2. 頁面規格

### 2.1 首頁／轉換器
主要內容：
1. 編號或網址輸入欄。
2. 來源選擇器與「自動判斷」狀態。
3. 產生結果及驗證訊息。
4. 複製、開啟、分享等操作。
5. 若來源具備可用且合適的預覽資料，顯示封面或摘要。
6. 最近使用紀錄的精簡入口。

互動原則：
- 輸入變更後即時更新或在明確提交後更新，兩者擇一並保持一致。
- 手動選擇來源時，不可被自動判斷悄悄覆蓋。
- 無效輸入要說明原因；不可把失敗的網址當成成功結果。
- 複製失敗時提供可選取的文字結果。
- 隨機編號僅對明確支援的來源顯示。

### 2.2 歷史記錄
- 顯示時間、來源、輸入值與目標網址。
- 支援搜尋、依最新／最舊排序、重新開啟、刪除單筆與清除全部。
- 空狀態提供返回轉換器的入口。
- 清除大量資料前要求確認。
- 不因刪除歷史記錄而連帶刪除收藏。

### 2.3 收藏
- 顯示已收藏項目及必要的來源資訊。
- 支援搜尋、排序、開啟與取消收藏。
- 第一版以基本收藏流程為優先；標籤、分類與備註可列入後續版本。
- 收藏更新與刪除要反映到本機資料及同步佇列。

### 2.4 碼表
- 顯示清晰、易讀的經過時間。
- 依狀態顯示開始、暫停、繼續、結束並保存。
- 顯示目前狀態，避免使用者不確定碼表是否正在運作。
- 離開再返回時，從持久化資料還原，不依賴背景每秒執行。
- 結束前可顯示確認或明確的結束按鈕；結束後建立一筆完成紀錄。
- 不加入倒數、番茄鐘、任務命名或分類。

### 2.5 碼表紀錄
- 依開始時間由新到舊排列。
- 顯示自動名稱、開始時間、結束時間及實際計時長度。
- 支援日期範圍、搜尋或排序。
- 單筆詳情可查看暫停區段與總計時時間。
- 提供每日／全部累計統計。
- 刪除紀錄前確認；刪除後同步刪除標記，避免舊資料重新出現。

### 2.6 設定
- 主題：淺色、深色、跟隨系統。
- GitHub 同步：登入狀態、最後同步時間、待同步數量、錯誤訊息與重試。
- 資料管理：匯出／匯入（格式與驗證規則待設計）、清除本機資料。
- 隱私與使用說明：明確列出同步的資料類型及保存位置。

## 3. 網站來源登錄規格

每個來源以獨立的設定或 adapter 管理，不將來源判斷散落在 UI 元件中。建議每個來源至少描述：

- `id`：穩定且唯一的內部識別碼。
- `name`：顯示名稱。
- `matchInput(input)`：判斷輸入是否符合此來源格式。
- `validateInput(input)`：驗證編號格式並回傳可讀錯誤。
- `buildUrl(input)`：產生目標網址。
- `capabilities`：是否支援預覽、隨機編號、分享或其他功能。
- `getPreview(input)`（可選）：從允許且穩定的資料來源取得預覽。
- `priority`：自動判斷發生歧義時的明確優先順序，或要求使用者手動選擇。

### 來源新增檢查清單
- [ ] 網站網址規則已核實，並以測試案例覆蓋。
- [ ] 輸入格式、邊界條件與無效值已定義。
- [ ] 來源服務條款、內容適當性與資料使用方式已確認。
- [ ] 預覽資料來源合法、穩定，且不依賴未授權的繞過方式。
- [ ] 不要求停用瀏覽器安全機制，也不收集不必要的使用者資料。
- [ ] 來源故障時有合理的錯誤狀態與降級行為。
- [ ] 新增來源不會改壞其他來源的轉換與測試。

具體支援來源清單目前先不預設。應在逐一確認來源、格式與適用範圍後，再新增至設定與測試。

## 4. 核心資料流

1. 使用者輸入編號或選擇來源。
2. 核心服務解析來源並驗證輸入。
3. 來源 adapter 產生網址。
4. 成功結果加入本機歷史記錄；使用者可另行收藏。
5. 本機資料層持久化變更。
6. 若已啟用 GitHub 同步，將變更排入同步佇列。
7. 同步成功後更新同步狀態；失敗則保留佇列並可重試。

UI 元件只負責呈現與互動，不應直接散落呼叫 GitHub API 或自行拼接來源規則。

## 5. 設計與品質原則

- 主要動作清晰；次要操作不要搶走視覺焦點。
- 不只依賴顏色表達錯誤或成功，並提供文字標籤。
- 載入中、無資料、離線、權限不足與來源失效都要有明確狀態。
- 重要操作提供可理解的確認與復原方式（可行時）。
- 所有列表均考慮空狀態、長內容與小螢幕。
- 使用語意化 HTML、鍵盤可操作控制項與明顯的焦點樣式。
- 任何同步失敗都不應讓使用者誤以為資料已成功上雲。
