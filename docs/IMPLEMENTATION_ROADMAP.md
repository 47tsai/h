# 實作路線圖

本文件記錄目前狀態與接下來值得處理的項目。程式碼是現況的最終依據。

## 已有功能

- Astro、Svelte、TypeScript、Tailwind CSS 4 的網站架構。
- 響應式導覽與淺色／深色／系統主題。
- 編號轉換器與多來源網址產生。
- 歷史紀錄、收藏、搜尋與排序。
- IndexedDB 本機保存。
- 純碼錶、紀錄列表及時間統計。
- JSON 備份匯入／匯出。
- Cloudflare Worker 手動同步，含資料驗證、合併、刪除標記與 GitHub SHA 衝突重試。
- GitHub Actions 網站與 Worker 部署流程。

## 接下來優先處理

### 1. 同步資料的公開性與存取控制

目前同步文件位於公開儲存庫 `data/sync.json`，內容可被任何人讀取。Worker 已移除同步密碼，Origin 檢查與限流不構成身分驗證。

需要決定是否把同步資料移到私人儲存庫，並為一鍵同步加入真正的授權機制。完成前不要將敏感內容放入同步文件。

### 2. 同步流程的資料安全

- 確認本機與雲端合併後的資料會正確套用。
- 確認同步失敗時不會遺失本機資料。
- 檢查刪除標記與相同 URL 合併的邊界情況。
- 視實際使用情況調整單一 JSON 檔案的大小與資料筆數限制。

### 3. 前端整理

- 將轉換來源規則從大型 UI 元件拆分成獨立模組。
- 檢查各來源的 ID 驗證與網址規則。
- 整理重複的 UI 邏輯與樣式，維持手機操作體驗。
- 保留必要的本機備份能力，避免使用者資料只依賴單一儲存位置。

### 4. 文件維護

- `SYNC_DESIGN.md`：同步流程與目前限制。
- `DATA_MODEL_AND_MERGE.md`：同步 schema 與合併規則。
- `WORKER_SECURITY_AND_DEPLOYMENT.md`：Worker 設定及部署方式。
- `TECHNICAL_DECISIONS.md`：目前已採用的技術選擇。
- `PROJECT_PLAN.md`、`INTERFACE_AND_SOURCE_PLAN.md`、`LOW_FIDELITY_WIREFRAMES.md`：保留作為需求與介面規劃參考，不代表現有程式已完全符合所有草案。

## 維護原則

- 優先修正會造成資料遺失、資料暴露或核心操作失效的問題。
- 規劃文件不得描述成已完成的功能。
- 實作與文件不一致時，先確認實際程式行為，再更新文件。
