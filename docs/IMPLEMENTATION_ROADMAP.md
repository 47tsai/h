# 實作路線圖

> 狀態：實作中。以下規劃項目仍須逐項驗收，不因部分功能已存在就視為整個階段完成。
>
> 本文件將既有需求、介面、資料模型與同步安全規格整理成可逐步完成的工作項目。每個階段都應先通過驗收，再進入下一階段；除非明確需要，不要一次引入所有功能。


## 目前實作進度（2026-10-12）

已提交並納入 CI 驗證流程的項目：

- 專案骨架：Astro、Svelte、TypeScript、Tailwind CSS 4 與 GitHub Actions。
- 工作區介面：響應式導覽、深色／淺色／系統主題。
- 純碼錶初版：開始、暫停、繼續、停止並儲存；進行中狀態以本機儲存恢復。
- IndexedDB v2：碼錶紀錄與收藏分表保存，具備新增／讀取／刪除操作。
- 收藏初版：網址、標題、備註、搜尋、開啟、重複網址更新與取消收藏。
- 資料層測試：使用 fake-indexeddb 驗證碼錶與收藏的保存、排序、更新及刪除。

仍未完成的重點：轉換器來源註冊表與實際來源規則、完整歷史管理與統計、收藏排序與編輯體驗、資料 schema 遷移測試、雲端同步 Worker，以及端到端與真實瀏覽器驗證。CI 通過只代表目前自動檢查通過，不代表尚未實作的功能已完成。

## 原則與工作方式

- 先完成最小可用骨架，再逐步擴充。
- 本機功能優先，雲端同步不能成為核心功能的依賴。
- 先定義資料契約與測試，再撰寫主要業務邏輯。
- 每個階段保持可建置、可測試、可回退。
- UI 元件避免直接混入資料儲存、轉換規則或 GitHub API 邏輯。
- 不把參考專案的程式碼當成本專案的實作基礎。
- 所有來源轉換器都必須遵守合法使用、服務條款與適用內容範圍。

## Phase 1：專案骨架與工程品質

### 工作項目

- [ ] 初始化 Astro 專案。
- [ ] 加入 Svelte、TypeScript 與 Tailwind CSS。
- [ ] 建立一致的目錄結構，分離頁面、UI、功能模組、資料存取與來源轉換器。
- [ ] 設定格式化、Lint、型別檢查與測試指令。
- [ ] 設定環境變數範例檔，只放公開設定，不放任何秘密。
- [ ] 建立基本導覽、錯誤頁與空白狀態。
- [ ] 設定 CI，在 Pull Request 或提交時執行檢查。

### 驗收條件

- 全新環境可依文件安裝依賴並啟動開發伺服器。
- 正式建置、型別檢查、Lint 與基本測試皆可通過。
- 前端建置檔不包含任何秘密。

## Phase 2：設計系統與響應式介面

### 工作項目

- [ ] 定義顏色、字級、間距、圓角、陰影與互動狀態等設計 Token。
- [ ] 建立按鈕、輸入框、選單、對話框、提示訊息、空白狀態與載入狀態等共用元件。
- [ ] 實作桌面版側邊導覽與手機版導覽。
- [ ] 實作 light、dark、system 三種主題。
- [ ] 將低擬真線框轉為實際頁面骨架。
- [ ] 檢查鍵盤操作、焦點可見性、對比度與基本無障礙需求。

### 驗收條件

- 手機窄螢幕與桌面寬螢幕均可正常操作。
- 不出現主要內容水平溢出或被固定導覽遮住。
- 主題切換一致，重整後設定仍有效。
- 主要操作有清楚的 hover、focus、disabled、loading 與錯誤狀態。

## Phase 3：轉換器核心與來源介面

### 工作項目

- [ ] 定義 SourceAdapter 型別與來源註冊表。
- [ ] 將來源識別、輸入驗證、URL 產生與錯誤訊息分離。
- [ ] 實作自動識別與手動選擇來源。
- [ ] 實作轉換結果顯示、複製、開啟及可行時的分享操作。
- [ ] 只有在來源規則可靠且合規時才提供預覽；無法確認時清楚顯示限制。
- [ ] 為每個來源建立正常輸入、錯誤輸入、邊界值與未知來源測試。
- [ ] 只加入已確認規則的第一批來源。

### 驗收條件

- 每個來源的規則都有獨立測試，不依賴 UI 測試才能驗證。
- 不會將未知輸入靜默轉成看似有效的 URL。
- 轉換錯誤有明確且可理解的提示。
- 來源可獨立新增或移除，不需要重寫主要頁面。

## Phase 4：本機資料層、歷史與收藏

### 工作項目

- [ ] 實作 IndexedDB 存取層與 schema migration 機制。
- [ ] 依資料模型實作歷史紀錄與收藏的新增、讀取、更新及刪除。
- [ ] 歷史紀錄保存來源、輸入 ID、產生的 URL 與時間。
- [ ] 實作歷史搜尋、排序、重新開啟與刪除。
- [ ] 實作收藏搜尋、排序、開啟與取消收藏。
- [ ] 加入空白狀態、錯誤狀態及資料載入狀態。
- [ ] 設定刪除與大量資料變更的確認方式。
- [ ] 驗證重新整理、關閉再開啟及離線情境下資料仍可用。

### 驗收條件

- 重整頁面不會遺失已保存資料。
- 歷史紀錄與收藏分開管理，操作其中一者不會意外修改另一者。
- 搜尋、排序、刪除與重新開啟功能行為一致。
- IndexedDB 暫時不可用時，顯示錯誤而不是假裝已保存。

## Phase 5：純碼錶與紀錄統計

### 工作項目

- [ ] 實作開始、暫停、繼續、停止及儲存流程。
- [ ] 使用時間戳計算經過時間，不以計時器回呼次數累加作為權威資料。
- [ ] 儲存開始與結束時間、總經過時間及自動產生的紀錄名稱。
- [ ] 重新進入頁面時恢復進行中或暫停中的碼錶狀態。
- [ ] 實作碼錶紀錄列表、搜尋、排序、詳情與刪除。
- [ ] 實作每日及累計統計。
- [ ] 明確處理跨日、背景分頁、裝置休眠與時鐘變更。
- [ ] 不加入倒數、番茄鐘或任務分類。

### 驗收條件

- 分頁背景化或裝置休眠不會造成經過時間嚴重偏差。
- 重新載入後可依儲存狀態正確恢復。
- 停止並儲存後，不會重複產生相同紀錄。
- 每日統計使用一致的時區與日期切分規則。

## Phase 6：設定與資料管理

### 工作項目

- [ ] 實作主題與介面偏好設定。
- [ ] 實作資料匯出與匯入的需求評估及驗證流程。
- [ ] 匯入時驗證 schema、欄位型別、資料筆數與檔案大小。
- [ ] 匯入前提供預覽或確認，避免無聲覆蓋現有資料。
- [ ] 設計損壞資料、舊版 schema 與重複資料的處理方式。

### 驗收條件

- 使用者可理解匯入會新增、更新或取代哪些資料。
- 無效匯入不會破壞現有資料。
- 設定與使用者資料的保存策略清楚分離。

## Phase 7：Cloudflare Worker 與 GitHub 手動同步

### 工作項目

- [ ] 依同步資料模型實作文件序列化與 schema 驗證。
- [ ] 建立 Worker，固定 GitHub 儲存庫、分支與資料路徑。
- [ ] 以 Worker Secrets 儲存 GitHub Token 與必要的驗證秘密。
- [ ] 實作專用同步密碼驗證、限流、請求大小限制與錯誤處理。
- [ ] 實作 GitHub 讀取、SHA 版本控制、合併、寫回與有限次重試。
- [ ] 實作多裝置衝突與刪除標記的合併規則。
- [ ] 前端只在使用者主動操作時同步。
- [ ] 顯示最後同步時間、同步結果及可理解的錯誤。
- [ ] 測試 Token 撤銷、錯誤密碼、GitHub API 限流與服務中斷。

### 驗收條件

- GitHub Token 不會出現在前端建置檔、瀏覽器儲存或 API 回應。
- 未授權請求無法讀寫同步文件。
- 同步失敗不會清除本機資料或誤報成功。
- 多裝置更新不會因簡單覆寫而靜默遺失資料。
- 本機功能不依賴 Worker 可用性。

## Phase 8：整合測試、效能與安全檢查

### 工作項目

- [ ] 為資料層、來源轉換器、碼錶與合併邏輯補齊單元測試。
- [ ] 使用 Playwright 測試主要使用流程。
- [ ] 測試手機與桌面版、light/dark/system 主題。
- [ ] 測試無網路、Worker 失敗、GitHub 限流與資料衝突。
- [ ] 檢查鍵盤可操作性、語意化標記與色彩對比。
- [ ] 檢查大型歷史紀錄的搜尋、排序與列表效能。
- [ ] 檢查依賴安全性、前端秘密洩漏及不必要的外部請求。

### 驗收條件

- 核心使用流程有自動化測試。
- 所有已知的高優先級錯誤均已處理或記錄為已接受風險。
- 測試失敗時能定位問題，不依賴人工猜測。

## Phase 9：部署與維護

### 工作項目

- [ ] 決定正式部署平台與網域設定。
- [ ] 設定正式環境變數與 Worker Secrets。
- [ ] 執行正式建置與部署前檢查。
- [ ] 驗證正式網址、HTTPS、快取行為與錯誤頁。
- [ ] 建立回滾方式與版本標記。
- [ ] 文件化 Worker Secret 輪替、GitHub Token 撤銷與資料備份流程。
- [ ] 部署後完成主要功能的冒煙測試。

### 驗收條件

- 新版本可重複部署，且部署失敗時有回復方案。
- 正式環境沒有開發用萬用 CORS 或測試秘密。
- 使用者知道資料存在哪裡，以及如何匯出或恢復。

## 建議的第一個開發切片

完成 Phase 0 後，第一個實際開發切片只涵蓋：

1. 初始化 Astro、Svelte、TypeScript 與 Tailwind CSS。
2. 設定格式化、Lint、型別檢查與基本測試。
3. 建立主版面、導覽與空白頁。
4. 確認手機與桌面版可建置、可瀏覽。
5. 提交一個可運作的最小骨架。

先不要在同一個切片中加入來源轉換、IndexedDB、碼錶或雲端同步。這樣可以先驗證技術堆疊與部署路徑，降低後續排錯成本。

本路線圖是開發順序與驗收依據，不代表任何階段已完成。每個核取項目應在實際完成並驗證後才勾選；若需求變更，需同步更新相關規格文件與測試。
