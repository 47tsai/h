# 專案規劃與注意事項

> 狀態：規劃中。本文是目前的需求基準，不代表已開始實作；技術選型與細節可在開發前調整。

## 1. 專案定位

建立一個以「多網站編號轉換」為核心的個人 Web 工具網站，並整合歷史記錄、收藏、純碼表、資料同步與個人化介面。

參考專案：[Godconverter_new](https://github.com/lokey0905/Godconverter_new)。

**參考原則：只借鑑功能與使用流程，不直接複製原始碼、視覺資產或未確認授權的內容。** 新專案依自身需求重新設計架構、介面與實作。

## 2. 產品目標

- 手機、平板與桌面瀏覽器都能順暢使用。
- 常用操作簡單直接，減少不必要的頁面跳轉。
- 新增網站來源時，不需要大幅修改核心程式。
- 本機資料保存可靠；GitHub 同步失敗時，基本功能仍可使用。
- 程式碼易於理解、測試與維護。

## 3. 功能規劃

### 3.1 多網站編號轉換

- 輸入編號後產生對應網址。
- 支援自動判斷來源，以及手動選擇來源。
- 網站來源以獨立設定／轉接器管理，包含編號驗證、網址產生與可用能力。
- 複製網址、分享、開啟原始頁面。
- 清除輸入、隨機編號（僅適用於支援且合理的來源）。
- 若來源提供合法且穩定的封面資料，可顯示預覽並處理載入失敗。
- 清楚呈現不支援的編號、無效輸入、網路錯誤與來源不可用等狀態。
- 網站來源清單、各來源的規則及可用性仍待確認；只加入合法、適當且符合相關服務條款的來源，不假設所有來源都支援相同功能。

### 3.2 歷史記錄

- 記錄每次轉換的來源、輸入編號、產生網址與時間。
- 支援搜尋、排序、重新開啟、刪除單筆及清除全部。
- 可設定合理的本機保存上限。
- 歷史記錄與收藏分開管理。
- 明確提示資料尚未同步、同步中或同步失敗。

### 3.3 收藏

- 收藏轉換結果或常用網址。
- 支援搜尋、排序、取消收藏與快速開啟。
- 名稱、備註、標籤或分類可視實作成本決定；第一版優先完成基本收藏流程。
- 收藏項目可與歷史記錄建立關聯，但刪除歷史不應意外刪除收藏。

### 3.4 純碼表與紀錄

本功能只做碼表，不做倒數計時、番茄鐘、任務命名或分類。

- 開始、暫停、繼續、結束並保存。
- 每次開始時建立新紀錄，名稱自動使用開始日期與時間。
- 保存開始時間、結束時間、累計計時長度、暫停區段及唯一識別碼。
- 暫停期間不計入累計時間。
- 關閉分頁、暫時離開網站或重新開啟瀏覽器後，應能還原未完成的計時狀態。
- 紀錄頁支援查看單筆詳情、依時間搜尋／排序、刪除，以及每日與總累計時間統計。
- 已完成紀錄先保存至本機，再排入 GitHub 同步；網路或 API 失敗不應使紀錄消失。

### 3.5 個人化與網站體驗

- 淺色、深色、跟隨系統。
- 響應式排版，優先確保手機觸控操作與窄螢幕可用性。
- 記住必要的使用者偏好與上次選擇。
- 可評估 PWA／加入主畫面支援；不承諾瀏覽器關閉後仍有背景即時執行能力。
- 提供載入中、空狀態、錯誤、成功與同步狀態提示。
- 注意鍵盤操作、焦點狀態、色彩對比與可讀性。

## 4. 頁面與導航草案

1. **首頁／轉換器**：編號輸入、來源選擇、結果、預覽與常用操作。
2. **歷史記錄**：搜尋、排序、重新開啟與刪除。
3. **收藏**：已收藏項目與快速操作。
4. **碼表**：目前計時狀態與開始／暫停／繼續／結束。
5. **碼表紀錄**：所有已保存紀錄與統計。
6. **設定**：主題、同步狀態、資料管理與使用說明。

導航形式（頂部導覽列、側邊欄或手機底部導覽）待介面草圖階段決定。

## 5. 初步技術方向

目前建議，但尚未鎖定：

- **框架：** Astro + Svelte
- **語言：** TypeScript
- **樣式：** Tailwind CSS
- **本機資料：** IndexedDB；少量非敏感偏好可用 localStorage
- **雲端同步：** GitHub API，搭配明確且安全的使用者授權流程
- **部署：** 可評估 GitHub Pages 或 Cloudflare Pages；同步授權方案確認後再決定
- **測試：** Vitest；核心使用流程再用 Playwright 做端到端測試

技術選型需先以最小原型驗證建置、路由、資料保存、部署與 GitHub 授權流程，再正式擴展。

## 6. GitHub 同步設計

預期同步資料包含歷史記錄、收藏、碼表紀錄與必要設定。

- 本機優先：主要功能不應要求使用者先登入 GitHub。
- 授權前先確認資料格式、同步範圍與使用者可控制的資料清除方式。
- 為每筆資料建立穩定的唯一 ID，並保存更新時間或版本資訊。
- 處理離線、重試、重複提交、衝突與同步中斷。
- 同步失敗時保留本機資料並提供可理解的狀態。
- 對使用者說明哪些資料會傳到 GitHub、存放位置與如何撤銷授權。

### 安全注意事項

- **絕不可將 Personal Access Token、OAuth client secret 或其他私密憑證寫入前端程式碼、公開設定檔或 Git 歷史。**
- 純靜態網站沒有可安全保存 client secret 的後端；必須先選擇適用於公開客戶端的安全授權流程（例如支援 PKCE 的流程），或使用受保護的後端／授權代理。不可用把 PAT 貼進前端的方式取代正式授權。
- 授權權限應遵守最小權限原則，只要求必要的存取範圍。
- 私有儲存庫不代表瀏覽器端憑證安全；不要把任何長期有效的祕密放進前端。
- 開發前需驗證 GitHub API 的權限要求、速率限制、衝突處理及部署環境相容性。

## 7. 碼表正確性注意事項

- 不以「每秒加一」作為計時真實來源，避免背景分頁節流導致時間偏差。
- 以開始／暫停／繼續等時間戳記與累計值計算經過時間。
- 每次狀態變更都要先持久化，再更新 UI；需要處理儲存失敗。
- 頁面重新載入時從保存狀態還原；已暫停的碼表不能把暫停時間算進去。
- 結束操作應具備防重複機制，避免同一筆紀錄被重複建立或同步。
- 明確定義「結束」後是否允許恢復；預設結束即封存，若要繼續需新建一筆紀錄。

## 8. 資料模型草案

實際欄位會在實作前再定稿。

- **HistoryItem：** id、sourceId、input、url、createdAt。
- **FavoriteItem：** id、sourceId（可選）、input（可選）、url、title（可選）、note（可選）、createdAt、updatedAt。
- **StopwatchSession：** id、startedAt、endedAt（可空）、status、elapsedBeforeCurrentRun、currentSegmentStartedAt（可空）、pauseEvents 或等價暫停資料、updatedAt。
- **Settings：** theme、lastSelectedSource、syncPreferences 等非敏感偏好。

不要把存取 Token 當成一般設定或同步資料保存。

## 9. 開發階段

### Phase 0：規劃與技術驗證
- 確認第一批網站來源與各自規則。
- 畫出主要頁面草圖。
- 驗證 Astro + Svelte 的基本架構與部署方式。
- 先確認 GitHub 授權與資料同步可行方案。

### Phase 1：網站骨架與轉換核心
- 建立共用版面、導航、主題與來源介面。
- 完成編號輸入、驗證、網址產生、複製與錯誤狀態。

### Phase 2：本機資料功能
- 完成歷史記錄、收藏與 IndexedDB 資料層。
- 加入純碼表、狀態還原與紀錄查看。
- 驗證關閉分頁、重新開啟及暫停情境。

### Phase 3：GitHub 同步
- 完成安全授權、同步資料格式、衝突處理與錯誤恢復。
- 測試不同裝置與離線／重新連線情境。

### Phase 4：品質與發布
- 完成響應式、可及性、錯誤處理與測試。
- 確認部署、隱私說明、使用方式與備份／清除資料流程。

## 10. 第一版驗收條件

- 來源規則集中管理，新增來源不需要重寫整個轉換器。
- 轉換結果正確，無效輸入有清楚提示。
- 歷史與收藏在重新載入後仍存在。
- 碼表離開再回來能還原；暫停時間不計入；結束只建立一筆紀錄。
- 碼表紀錄可以完整查看、搜尋／排序及刪除。
- 未登入或 GitHub 同步失敗時，核心功能與本機資料仍可使用。
- 公開前端不包含任何長期有效的私密憑證。
- 手機與桌面主要流程皆經過測試。
